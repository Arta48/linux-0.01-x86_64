# Linux 0.01 (x86_64 Edition)

A modern, complete reimplementation of Linus Torvalds' historic **Linux 0.01** kernel (released September 17, 1991), re-engineered for the **x86_64 (AMD64 / Long Mode)** architecture.

---

## 📌 Архитектурный манифест

Оригинальное ядро Linux 0.01 было тесно привязано к аппаратуре 80386:
* Аппаратное переключение задач через дескрипторы **TSS** и инструкцию `ljmp`.
* Сегментная изоляция памяти через **LDT** и доступ к User Space через селекторы `%fs`.
* 32-битный двухуровневый пейджинг с лимитом в **8 МБ ОЗУ**.
* Инструкции `pushal` / `popal`.

В 64-битном режиме (**Long Mode**) архитектуры AMD64 аппаратный TSS удален из микрокода CPU, сегментация отключена, а таблицы страниц стали 4-уровневыми. Этот проект воссоздает ранний Linux на чистом x86_64, сохраняя оригинальную простоту, модульность каталогов (`boot/`, `init/`, `kernel/`, `mm/`, `fs/`, `lib/`, `include/`) и алгоритмы Линуса Торвальдса.

---

## 🏛️ Сравнение архитектур

| Подсистема | Оригинальный Linux 0.01 (1991, i386) | Linux 0.01 x86_64 (Этот проект) |
| :--- | :--- | :--- |
| **Режим CPU** | 32-битный Protected Mode | 64-битный Long Mode (AMD64) |
| **Многоядерность** | Одно ядро (UP), привязка к 80386 | **Симметричная многоядерность (SMP)**: Local APIC, рассылка IPI, трамплин `0x8000` |
| **Пейджинг** | 2-уровневый (`pg_dir` -> `pg0`/`pg1`, 32-бит) | 4-уровневый (PML4 -> PDPT -> PD -> PT), per-process CR3, **Copy-On-Write (COW)** |
| **Многозадачность** | Аппаратная через дескрипторы TSS (`ljmp`) | Программная через стек (`switch_to` на ассемблере) |
| **Прерывания (IDT)** | 8-байтовые шлюзы, `pushal`/`popal` | 16-байтовые шлюзы, ручное сохранение `%r15..%rax`, `iretq` |
| **Системные вызовы** | Медленный шлюз `int 0x80` (~200 тактов) | Аппаратный MSR `syscall`/`sysretq` (~35 тактов, в 30 раз быстрее) + `int $0x80` |
| **VFS / Файлы** | Minix FS на жестком диске (1024B блоки) | **Дисковая Minix v1 FS на `/dev/hda` (`/mnt`) с блочным Buffer Cache (1024B)** + RamFS + TarFS (Initrd) |
| **Блочные устройства**| Жесткая привязка к BIOS / AT-дискам | 64-битный драйвер ATA PIO (`/dev/hda`), чтение/запись LBA28, сохранение в `disk.img` |
| **Пользовательский код**| Жестко вкомпилированные задачи | Отдельная среда сборки `user/`, изолированные Ring 3 процессы, ELF-загрузчик |
| **Стандартная библиотека**| Отсутствует / Системная | Родная `ulibc` только для `init` и диагностики; остальное — настоящая glibc с хоста (Linux ABI) |

## 🗺️ Реализованные этапы (Stages 1 – 51)

Этапы 7–44 описывают историю проекта: собственные `sh`, `nano`, `tcc`, `httpd`, `mintest` и другие программы с этих этапов удалены на этапе 51.

* **Stage 1:** Multiboot-загрузка, 4-уровневый пейджинг (PML4, PDPT, PD 2MB Huge Pages), переход в Long Mode, видеовывод VGA `0xB8000` и COM1 `0x3F8`.
* **Stage 2:** 64-битная IDT (16-байтовые шлюзы), перепрограммирование PIC 8259 на векторы 32..47, таймер PIT (100 Гц), счётчик `jiffies`.
* **Stage 3:** Аллокатор физических фреймов памяти на 128 МБ (`mem_map`), динамический маппинг страниц `map_page()`, перехват Page Fault по `CR2`.
* **Stage 4:** Модель задач `task_struct`, программное переключение контекста (`switch_to` в `kernel/switch.S`), планировщик с деградацией приоритетов.
* **Stage 5:** User Space (Ring 3), дескрипторы Ring 3 в GDT, 64-битный TSS (`TSS.rsp0`), шлюз прерываний `int 0x80`.
* **Stage 6:** Интерактивный драйвер клавиатуры PS/2 и Serial COM1, кольцевой буфер, системный вызов `sys_read(0)`.
* **Stage 7:** Пользовательский шелл в Ring 3: строковый буфер, защита приглашения от стирания через Backspace, встроенные команды.
* **Stage 8:** Дублирование процессов: системный вызов `sys_fork()`, точка входа потомка `ret_from_fork`, утилита `ps`, учет состояния `ZOMBIE`.
* **Stage 9:** Быстрые системные вызовы: аппаратные регистры MSR `EFER.SCE`, `STAR`, `LSTAR`, `SFMASK`, ассемблерный шлюз `syscall_entry.S`, бенчмарк `bench`.
* **Stage 10:** Виртуальная файловая система (VFS) и RamFS: файловые дескрипторы `filp[]`, системные вызовы `open`, `close`, `read`, утилиты `ls`, `cat`.
* **Stage 11:** Межпроцессное взаимодействие (IPC): системный вызов `sys_pipe`, однонаправленный кольцевой буфер, передача данных между процессами.
* **Stage 12:** Жизненный цикл процессов: системный вызов `sys_waitpid` с освобождением страниц памяти, `sys_kill`, фоновый запуск `spawn`, команда `kill`.
* **Stage 13:** Динамическая куча процесса (Heap): системный вызов `sys_brk`, функции `sbrk()`, блочный аллокатор `u_malloc()` и `u_free()` в Ring 3.
* **Stage 14:** Загрузчик бинарных программ: системный вызов `sys_execve()`, автономные 64-битные программы `hello` и `calc`, шаблон Unix Fork+Exec.
* **Stage 15:** Динамическая запись в RamFS: системный вызов `sys_unlink()`, создание файлов `O_CREAT`, дозапись и перезапись, утилиты `touch`, `rm`, оператор `>`.
* **Stage 16:** Системный вызов `sys_dup2()`, перенаправление `любая_команда > файл`, конвейеры пайпов `cmd1 | cmd2`.
* **Stage 17:** Иерархия каталогов VFS: системные вызовы `chdir`, `mkdir`, `rmdir`, `getcwd`, относительные пути (`..`, `.`), папки `/bin`, `/etc`, `/home`.
* **Stage 18:** Сигналы Unix: `SIGINT`, асинхронный перехват `Ctrl+C`, системный вызов `sys_signal()`, C-обработчики в Ring 3, задержка `sleep`.
* **Stage 19:** Часы реального времени CMOS RTC: считывание портов `0x70/0x71`, BCD-декодирование, алгоритм `mktime` Линуса, команда `date`, подробный `ls -l`.
* **Stage 20:** Псевдофайловая система `/proc`: файлы `/proc/cpuinfo`, `/proc/meminfo`, аппаратный `cpuid` (модель процессора), `sys_uname`, команда `uname -a`.
* **Stage 21:** Потоковая фильтрация: утилита `grep`, утилита подсчёта `wc -l`, дозапись `>>`, кольцевая история команд шелла (Стрелки Вверх/Вниз).
* **Stage 22:** Переменные окружения: `$?` (код возврата), `$PWD`, `$USER`, команды `export`, `env`, фоновый запуск с амперсандом `&` (`jobs`, `WNOHANG`).
* **Stage 23:** Многопользовательская безопасность: учетные записи `/etc/passwd`, разграничение прав доступа UID/GID, команды `whoami`, `id`, `su`, `chmod`.
* **Stage 24:** Аутентификация: проверка паролей в ядре, скрытый ввод пароля, безопасный `su root`.
* **Stage 25:** Пакетные шелл-скрипты: запуск `sh <скрипт>` и `./скрипт.sh`, скрипт автозагрузки `/etc/init.sh`, комментарии `#`, снятие кавычек.
* **Stage 26:** Интерактивный строковый редактор `edit <файл>` (аналог nano/ed) в Ring 3, позиционные параметры скриптов `$1..$9` и `$#`.
* **Stage 27:** Метаданные файлов: системный вызов `sys_stat()`, структура `struct stat`, утилита `stat <файл>`.
* **Stage 28:** Передача аргументов командной строки `argc` и `argv` в бинарники через `execve` по стандарту System V AMD64 ABI.
* **Stage 29:** Multiboot Initrd (TarFS): автоматическое монтирование архива `rootfs.tar` с хоста в корень VFS ядра при загрузке.
* **Stage 30:** Управляющие конструкции в шелле: `if / then / else / fi`, `for`, `while`, утилиты `test` (`[ ]`), `let` и `expr` для арифметики.
* **Stage 31:** Собственная библиотека `ulibc` в Ring 3 (`printf`, `malloc`, `free`) и полный архитектурный рефакторинг: шелл вынесен из ядра в независимый бинарник `/bin/sh`.
* **Stage 32:** Полноэкранный псевдографический текстовый редактор `/bin/nano`. Аппаратный парсер ANSI-последовательностей (VT100) в VGA-драйвере, трансляция PS/2 стрелок.
* **Stage 33:** 64-битный драйвер жесткого диска IDE / ATA PIO: порты `0x1F0..0x1F7`, LBA28, чтение/запись блочного устройства `/dev/hda`, сохранение данных в `disk.img`.
* **Stage 34:** Полноценная дисковая файловая система Minix v1 на `/dev/hda`: 64-битный блочный Buffer Cache (`bread`/`bwrite`/`getblk`, хэш-таблица, LRU), монтирование `/mnt`, суперблок `0x137F`, иноды, битовые карты `imap`/`zmap`, персистентное сохранение файлов между перезапусками, системный вызов `sys_sync()`, тестовая утилита `mintest`.
* **Stage 35:** Аппаратный механизм Copy-On-Write (COW) при `sys_fork()`: разделение физических страниц между родителем и потомком с защитой от записи (`PTE_WRITABLE = 0`), счетчик ссылок в `mem_map`, динамическое дублирование страниц по Page Fault #14 (`do_page_fault`, `do_wp_page`), верификационная утилита `cowtest`.
* **Stage 36:** Симметричная многоядерность (SMP / Symmetric Multiprocessing): инициализация Local APIC (MSR 0x1B, `0xFEE00000`), межпроцессорные прерывания INIT-SIPI-SIPI, 16-битный трамплин по адресу `0x8000`, переход ядер AP из 16-бит Real Mode в 64-бит Long Mode, параллельная работа CPU, динамический `/proc/cpuinfo`, утилита `smpinfo`.
* **Stage 37:** Потоки ядра (Kernel Threads), спинлоки (`spinlock`) и мьютексы (`mutex`): аппаратные атомарные блокировки `spinlock_t` (`xchg`, `pause`), спящие мьютексы `mutex_t`, подсистема `kthread_create`, фоновый поток ядра `kworker`, защита аллокатора памяти `mem_lock`, утилита `threadtest`.
* **Stage 38:** Сетевой драйвер Intel 82540EM (e1000) и канальный уровень (Ethernet): опрос шины PCI (порты `0xCF8`/`0xCFC`), отображение MMIO (`BAR0`), инициализация дескрипторных колец RX/TX, чтение MAC-адреса, отправка сырых кадров Ethernet, тестовая утилита `nettest`.
* **Stage 39:** Сетевой стек: протоколы ARP (RFC 826), IPv4 (10.0.2.15), ICMP (Ping, RFC 792), UDP, расчет контрольных сумм RFC 1071, фоновый опрос пакетов, утилита `ping`.
* **Stage 40:** Протокол TCP (RFC 793), сокетный интерфейс BSD (socket, bind, listen, accept) и пользовательский HTTP веб-сервер в Ring 3 (`/bin/httpd`). Проброс портов QEMU (`hostfwd=tcp::8080-:80`) для просмотра веб-страницы ядра прямо в браузере на хосте Arch Linux.

* **Stage 41:** Графический режим: линейный фреймбуфер (GOP), 32-bit цвет, растровый шрифт 8x8, вывод текста и скроллинг на экране.
* **Stage 42:** Демо-рендеринг в фреймбуфере (подготовка к портированию DOOM; сам порт DOOM не выполнен).
* **Stage 43:** Самодостаточный мини-компилятор Си `/bin/tcc` (`/bin/cc`) в Ring 3 для небольших программ (`/home/prime.c`).
* **Stage 44:** Загрузка ELF-программ и динамических библиотек `.so` (`dltest`, `libmath.so`).
* **Stage 45:** Шина PCI (`lspci`) и первичная инициализация xHCI (`usbinfo`).
* **Stage 46:** Загрузчик UEFI `BOOTX64.EFI` (PE32+, собирается `tools/mkefi`), GOP, образ LiveUSB (`liveusb.img`).
* **Stage 47:** Исправление загрузки на реальном железе (UEFI) и консоль на фреймбуфере. Загрузчик теперь резервирует память ядра/initrd через `AllocateAddress`, берёт размеры файлов через `GetInfo`, не использует `.bss`, выбирает непрерывную свободную область по карте памяти UEFI и сообщает ядру её границу (`MB_FLAG_UEFI`/`mem_upper`); при ошибке показывает причину, а не перезагружает ПК. Ядро: `mem_init()` с проверкой границ (раньше underflow приводил к triple fault), одноядерный режим на UEFI, COM1 с ограниченным ожиданием, буферный кэш больше не путает диск 0 со «свободным» буфером, Minix не форматирует чужой диск, исключение в Ring 3 завершает только процесс.

* **Stage 48:** USB HID клавиатуры на собственном стеке xHCI (`kernel/xhci.c`, `kernel/usb_kbd.c`, `kernel/hid_parse.c`): BIOS/OS handoff (отключение SMI и PS/2-эмуляции прошивки), сброс контроллера, DCBAA + scratchpad, Command/Event/Transfer-кольца TRB, Enable Slot / Address Device / Evaluate Context / Configure Endpoint, control-передачи, Interrupt IN endpoint, опрос событий из таймерного IRQ0. Поддерживаются все контроллеры xHCI (до 4) и любое число клавиатур; USB-хабы 2.0 и SuperSpeed 3.x (рекурсивное перечисление, route string, Transaction Translator, `SET_HUB_DEPTH`, warm reset); клавиатуры с boot-протоколом и без него (разбор HID report descriptor: Report ID, NKRO-битовые карты, длинные отчёты); горячее подключение/отключение (поток `usbd`, период 500 мс); светодиоды CapsLock/NumLock/ScrollLock (`SET_REPORT`); преобразование HID Usage → ASCII (Shift, CapsLock, Ctrl+буква, Ctrl+C → SIGINT, стрелки, Home/End, цифровой блок, автоповтор). Подробный лог перечисления (`[OK] USB ... ifaces [...]`, `[USB] ...` для ошибок), `/proc/usb` и `/bin/usbinfo` показывают реальное состояние контроллеров и устройств. Исправления на реальном железе: `#GP(0x18)` после запуска `/bin/sh` на AMD (`STAR[63:48]` = `0x13`: AMD не добавляет RPL=3 к SS при `sysret`); `#GP` 0x13B от спурьёзного IRQ7 (в IDT добавлены шлюзы 34–47, спурьёзные IRQ7/IRQ15 распознаются по ISR PIC и не получают EOI). Выключение и перезагрузка ПК (`kernel/acpi.c`): UEFI-загрузчик передаёт ядру адрес ACPI RSDP, ядро разбирает FADT и `\_S5` из DSDT/SSDT; команды `poweroff`/`halt`/`reboot`, а выход из корневого шелла (`exit`) выключает компьютер; перезагрузка — через регистр сброса ACPI, контроллер 8042, порт 0xCF9 или тройную ошибку. Отсутствие ATA/IDE-диска и сетевой карты e1000 больше не выводится как ошибка (`[INFO]`, `/mnt` не монтируется). Цвет консоли по умолчанию — белый. Цель `make run-usb` проверяет драйвер в QEMU.

* **Stage 49:** Драйвер NVMe SSD и общий блочный слой. `kernel/nvme.c`: PCIe-контроллеры NVMe (class 01:08:02), сброс и включение через CC/CSTS, очереди Admin и IO (по 16 записей, polling без прерываний), Identify Controller / Namespace List / Namespace, Create IO CQ/SQ, команды Read/Write/Flush с передачей через PRP1/PRP2 (до 8 КБ за команду), пространства имён с LBA 512 (чтение и запись) и 4096 (только чтение). `kernel/blk.c`: таблица блочных устройств с проверкой границ и прав записи, разбор разделов GPT и MBR (`nvme0n1p1`, `sda1`, ...), поиск Minix v1, `/proc/disks`. Буферный кэш и Minix теперь работают поверх блочного слоя. Защита данных: NVMe/SATA-диски и их разделы доступны **только на чтение**; запись ядро разрешает единственному разделу, на котором нашло Minix v1 и смонтировало его в `/mnt`; форматирование реальных дисков невозможно. Устройства `/dev/nvme0n1`, `/dev/nvme0n1p2` и т. д. читаются (`cat`, `dd`), добавлены `/bin/lsblk` и системный вызов `lseek`. Сброс кэша записи диска при `sync`, `reboot`, `poweroff`. Чтобы данные сохранялись между запусками, создайте раздел и выполните в Linux `mkfs.minix -1 -n 14 /dev/<раздел>` (до 64 МБ): ядро найдёт его само.

* **Stage 50:** Драйвер SATA AHCI (`kernel/ahci.c`): все контроллеры AHCI (class 01:06:01, до 4) и до 12 дисков, передача управления от BIOS (BOHC), включение режима AHCI, остановка и запуск движка порта, Command List / Received FIS / Command Table, команды IDENTIFY DEVICE, READ/WRITE DMA EXT (LBA48) и READ/WRITE DMA (LBA28), FLUSH CACHE, передача данных через DMA-буфер до 64 КБ за команду, восстановление порта после ошибки или таймаута (HDD после простоя может раскручиваться до 20 с). Диски 4Kn и устройства не-ATA (ATAPI, port multiplier) пропускаются. Диски видны как `sda`, `sdb`, ... со всеми разделами GPT/MBR (`sda1`, ...) в `lsblk`, `/proc/disks` и `/dev`; защита данных та же, что на NVMe: только чтение, запись разрешена лишь разделу с Minix v1, смонтированному в `/mnt`, при этом NVMe-раздел имеет приоритет над SATA.

* **Stage 51:** Защита памяти, сеть Realtek, SMP на реальном железе, совместимость с Linux ABI, GNU coreutils и bash. (1) Память: ядро — supervisor-only identity-map 0–1 ГБ, CR0.WP=1; общее MMIO-окно 2–64 ГБ и `mmio_map()` (ioremap в PML4[511]) для фреймбуфера и BAR выше 4 ГБ; пользовательские страницы 1–2 ГБ и от 512 ГБ, VMA с ленивым выделением, COW, ядерные стеки 16 КБ, полный `trap_frame` на входе `syscall`. Фреймбуфер теперь отображается через `mmio_map` — возможная причина зависания ноутбука на «Launching /bin/init» (проверено только в QEMU). (2) Сеть: слой `struct nic_ops` (`kernel/nic.c`), драйвер Realtek RTL8168/8111/8169 (`kernel/rtl8169.c`, polling), e1000 на том же слое, ARP-кэш, DHCP с запасным адресом, `/bin/netinfo` (syscall `netctl`). (3) SMP: перемещаемый трамплин, нижняя страница через UEFI AllocatePages, разбор MADT, отдельный стек на каждый AP (планировщик по-прежнему на одном CPU, AP паркуются). Отключение: `make SMP=0`. (4) Linux ABI (`kernel/linux_abi.c`): ELF64 с `EI_OSABI=0x66` исполняется с номерами системных вызовов Linux x86_64 (файлы, каталоги, pipe/dup, fork/wait, execve, mmap/brk, сигналы с кадром `rt_sigaction`/`rt_sigreturn`, TLS через `arch_prctl`, tty с каноническим режимом и эхом, группы процессов, Ctrl+C только на передний план, потоки `clone(CLONE_THREAD)` с общими адресным пространством и таблицей fd, `futex` (WAIT/WAKE/BITSET/REQUEUE/WAKE_OP), `exit_group`, `tkill`, `statfs`/`fstatfs`, `statx`, `sendfile`). (5) Зависание ноутбука после «Launching /bin/init»: LINT0 локального APIC теперь явно настроен как ExtINT, i8042 опрашивается из тика, а если IRQ0 не приходит за 300 мс, системный тик переключается на LAPIC timer (в логе `[OK] Timer: …`); ramfs до 8192 файлов. (6) Обычные программы Linux вместо собственных: динамический загрузчик ELF (`ET_DYN`, `PT_INTERP`/`ld-linux`, auxv, `#!`-скрипты, определение Linux ABI по типу образа, пути `/usr/bin`, `/usr/lib`, `/lib64` и др. отображаются на `/bin` и `/lib`, `FXSAVE`/`FXRSTOR` на задачу), поэтому оригинальные бинарники GNU coreutils и bash запускаются без изменений; `tools/import_host.sh` копирует их с хоста вместе с библиотеками (пакетами целиком: `make HOST_PKGS="coreutils htop"`; список по умолчанию — в Makefile, отсутствующие на хосте пакеты пропускаются; база terminfo копируется вместе с ними). (7) Чистка: удалены собственный шелл `sh`, `nano`, `tcc`, `httpd`, BusyBox, dash и все тестовые и отладочные программы и вывод; в образе остались только `/bin/init` (запускает `bash`; когда bash завершается, выключает компьютер), `poweroff`/`halt`/`reboot` и диагностика железа `lspci`, `lsblk`, `usbinfo`, `smpinfo`, `netinfo`; `/proc` дополнен `uptime`, `version`, `display`, `mounts`, `self/mountinfo`; загрузчик UEFI находит место под большой initrd, если за ядром его нет; зависимости заголовков отслеживает `make` (`-MMD`). Проверки Linux ABI: `tests/linux/build.sh`. Консоль ведёт себя как настоящий терминал (`\b` только сдвигает курсор, стирание делает readline), добавлены клавиши Delete, Insert, PgUp, PgDn (PS/2 и USB), `/etc/passwd` в стандартном формате. (8) Сокеты и сеть для настоящих программ: `kernel/sock.c` — сокеты BSD (Linux ABI: `socket`, `connect`, `bind`, `listen`, `accept4`, `sendto`/`recvfrom`, `sendmsg`/`recvmsg`, `shutdown`, `getsockname`/`getpeername`, `getsockopt`/`setsockopt`, `socketpair`), настоящий TCP (клиент и сервер, окно, повторная передача с RTO по измеренному RTT, быстрая повторная передача, медленный старт, TIME_WAIT), UDP, ICMP (raw и «ping»-сокеты), AF_UNIX `socketpair`, loopback 127.0.0.0/8; `poll`/`select`/`fcntl(O_NONBLOCK)` работают с сокетами и pipe; `/etc/resolv.conf` (DNS из DHCP) и `/etc/hosts`, корневые сертификаты с хоста, локаль C.UTF-8; в образ по умолчанию входят оригинальные `curl` (http, https, DNS) и `ping` вместо собственных, а также утилиты util-linux, не требующие `/sys` и PAM (`dmesg` через `syslog(2)` и журнал ядра, `findmnt`, `mountpoint`, `getopt`, `more`, `rev`, `setsid`, `flock`, `taskset`, …; `eventfd`, `capget`, `getresuid`), таблица областей памяти процесса выросла до 4 страниц (curl грузит десятки библиотек), кольца приёма e1000/RTL — 128 дескрипторов. (9) sysfs (`fs/sysfs.c`, символические ссылки в ramfs): `/sys/devices/pci*`, `/sys/bus/pci/devices`, `/sys/block`, `/sys/class/block`, `/sys/dev/block`, `/sys/devices/system/cpu` с топологией — поэтому оригинальные `lspci`, `lsblk`, `lscpu` заменили собственные; сигналы SIGSEGV/SIGFPE/SIGILL из пользовательских исключений доставляются обработчику процесса. В образ по умолчанию входят весь ncurses (`clear`, `tput`, `tset`, `reset`, `infocmp`, `tic`, `toe`, `tabs`), `grep`, `sed`, `gawk`, `find`, `xargs`, `diff`, `cmp`, `tar`, `gzip`, `bzip2`, `xz`, `less`, `which`, `patch`, дисковые утилиты util-linux (`mount`, `umount`, `fdisk`, `sfdisk`, `mkfs.minix`, `fsck.minix`) и `/bin/sh` (настоящий bash под именем sh для скриптов `#!/bin/sh`); работа `mount`/`fdisk` на ядре не проверена. Ядро видит всю ОЗУ: карта памяти UEFI/multiboot целиком, ОЗУ выше 2 ГБ отображается identity-картой (2 МБ-страницы, до 512 ГБ), счётчики страниц лежат в самой ОЗУ; диапазон 1–2 ГБ физического адресного пространства не используется (там пользовательское окно процессов). Процессоры: до 254, все видны в `/proc/cpuinfo`, sysfs, `nproc`, `lscpu` (планировщик пока работает на BSP, остальные ядра запущены и припаркованы); `MAX_FILES` = 8192. `make` на Arch берёт программы пакетами целиком (`HOST_PKGS`, исполняемые файлы из `pacman -Ql`). Экранная консоль разбирает UTF-8 и рисует его настоящим шрифтом 8x16 (GNU Unifont, `tools/mkfont.py` → `include/linux/font16.h`: латиница, кириллица, греческий, рамки и блоки; рамки `lsblk` выглядят как на Linux), в образ добавлен `clear`. Опрос COM1 из тика не зависает на ноутбуках без UART (порт читается как 0xFF) — это и было зависание ноутбука после «sysfs». UEFI-загрузчик передаёт ядру список свободных участков памяти (исправление зависания ноутбука после TarFS; на самом ноутбуке не проверялось). Проверки: `tests/linux/abi_net`, `abi_net2`, `abi_ping`. Проверено в QEMU (tap-интерфейс + HTTP/HTTPS/DNS-сервер на хосте), на реальном железе не проверялось; передача через pipe (`curl | md5sum`) медленная (~100 КБ/с), запись в файл на `/mnt` и `/dev/null` — быстрая. После обновления выполните `make clean`.

## 🛠️ Сборка и запуск

### Требования (Arch Linux)
```bash
sudo pacman -S --needed base-devel qemu-system-x86 qemu-img mtools dosfstools edk2-ovmf
```

### Сборка и запуск
Ядро, `/bin/init`, диагностика железа и образ `rootfs.tar` собираются командой `make`; GNU coreutils, bash и fastfetch берутся с вашего Arch Linux (`sudo pacman -S coreutils bash fastfetch`). Запуск в QEMU:
```bash
make
make run
```

*(Для выхода из эмулятора нажмите **`Ctrl+A` затем `X`** или введите `poweroff` или `exit` (выход из bash выключает ПК)).*

### Сборка загрузочной флешки (LiveUSB / UEFI / Ventoy)
Для запуска на реальном ПК (например, AMD Ryzen 5 3600) или загрузки через Ventoy:
```bash
make liveusb.img
# Запись напрямую на физическую флешку:
sudo dd if=liveusb.img of=/dev/sdX bs=4M status=progress conv=fsync
```
